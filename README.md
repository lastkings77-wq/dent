# Стомато PWA — локальная стоматологическая CRM

Русскоязычное устанавливаемое PWA для iPhone: картотека пациентов, история лечения, расписание, зубная формула FDI, несколько клиник с разной долей клиники, доходы/расходы/долги и зашифрованные резервные копии.

## Важные ограничения и честный статус

- Проект написан как автономный PWA, без аналитики и серверной отправки данных.
- Данные приложения шифруются в IndexedDB с AES-GCM-256; ключ получается из пароля через PBKDF2-SHA-256 (310 000 итераций).
- Код в этой поставке **не следует считать прошедшим полноценное тестирование на реальном iPhone**. Перед реальной клинической эксплуатацией проверьте сценарии ниже.
- Приложение не заменяет официальную медицинскую карту клиники, требования законодательства и регламент хранения медицинских данных.
- Веб-приложение не может гарантировать защиту от взломанного/скомпрометированного устройства, вредоносных расширений, скриншотов или доступа к разблокированному телефону.
- Пароль не хранится. Если он утерян, расшифровать локальную базу нельзя.
- Установка PWA и Service Worker требуют HTTPS (или localhost для разработки). Не открывайте `index.html` напрямую через `file://`.
- Приложение хранит данные только в браузере на этом устройстве. Очистка данных Safari, удаление сайта или потеря телефона могут привести к потере базы. Регулярно делайте экспорт.
- Экспорт — зашифрованный JSON; пароль резервной копии отличается от пароля приложения. Храните файл и пароль раздельно.
- Для медицинских данных не используйте общедоступные Wi-Fi для администрирования устройства, включите код-пароль iPhone и авто-блокировку. Для реальной клиники отдельно оцените местные требования по защите персональных и медицинских данных.

## Файлы

- `index.html` — структура интерфейса.
- `styles.css` — адаптивные стили для телефона.
- `app.js` — логика, локальное шифрование, CRUD, финансы, импорт/экспорт.
- `manifest.webmanifest` — параметры PWA.
- `sw.js` — кеширование приложения для офлайн-запуска.
- `icon.svg` — иконка.

## Как запустить бесплатно

Нужен статический HTTPS-хостинг. Для бесплатного теста можно использовать GitHub Pages (публичный репозиторий означает, что **исходный код** виден другим; пациентские данные в репозитории размещать нельзя). Альтернатива — любой собственный HTTPS-хостинг.

1. Распакуйте ZIP.
2. Загрузите содержимое папки в отдельный репозиторий GitHub. Не добавляйте никакие данные пациентов.
3. В GitHub откройте **Settings → Pages**, выберите публикацию из ветки `main` и корневой папки `/root`, сохраните.
4. Дождитесь HTTPS-ссылки GitHub Pages.
5. Откройте ссылку в Safari на iPhone.
6. При первом запуске задайте длинный уникальный пароль (рекомендуется парольная фраза из нескольких случайных слов).
7. Добавьте клиники, затем пациентов и записи.
8. В Safari нажмите **Поделиться → На экран «Домой»**. В зависимости от версии iOS формулировка может немного отличаться.
9. Создайте зашифрованную резервную копию и убедитесь, что можете найти файл.

## Проценты клиник

Поле «Доля клиники, %» — процент от суммы поступления, который забирает клиника. Например, при оплате 1 000 000 сум и доле клиники 60% отчёт показывает 600 000 сум клинике и 400 000 сум вашей доли. Процент применяется к операциям типа «Поступление». Расходы в текущей версии вычитаются из общего результата полностью; если нужно учитывать расходы по каждой клинике и долю материалов отдельно, расширьте финансовую модель до запуска в работе.

Долг в этой версии — отдельная запись суммы к получению и не является поступлением денег. После оплаты долга нужно вручную добавить операцию «Поступление»; автоматического связывания долга и оплаты пока нет.

## Рекомендуемый тест-план перед использованием

1. Первый запуск: пароль короче 10 символов должен быть отклонён.
2. Создание базы, блокировка, вход с правильным паролем.
3. Неверный пароль: данные не должны перезаписываться.
4. Добавление двух клиник с долями 60% и 50%.
5. Добавление пациента, заметок и заметки на зубе FDI (например, 16).
6. Добавление, изменение и отмена записи; проверьте даты и время.
7. Добавление поступления 1 000 000 сум в клинике с долей 60%: доля клиники должна быть 600 000 сум, ваша — 400 000 сум.
8. Добавление расхода и долга; проверьте итоги и ручное отражение погашения долга.
9. Экспорт, блокировка, импорт копии в тестовой базе; проверьте неверный пароль и отмену замены.
10. Проверка офлайн-запуска после первого открытия по HTTPS.
11. Перезапуск Safari и iPhone; убедитесь, что данные доступны после ввода пароля.
12. Проверка на iPhone с актуальной iOS и Safari, включая установку на экран «Домой».

## Разработка и проверка

Это статическое приложение, сборка не требуется. Для локального теста можно запустить любой локальный HTTP-сервер, например `python3 -m http.server 8080`, но Web Crypto/Service Worker полноценно проверяйте через localhost или HTTPS.

Перед использованием реальных пациентов рекомендуется провести код-ревью, тесты в Safari/iOS, аудит безопасности и юридическую проверку требований к медицинским данным.
